# 星环算力平台调度（OJ 1846）——程序说明

## 文件

| 文件 | 用途 |
| :--- | :--- |
| `submit.cpp` | **提交用**：14905 字节（限制 16384），ASCII、LF，保留了变量名 |
| `submit_min.cpp` | 备用提交版：11196 字节，标识符全部缩短；逻辑与上面完全相同 |
| `main.cpp` | 阅读版：带注释、不含调试代码（29 KB，超限，不能直接交） |
| `sol.cpp` | 开发版：阅读版 + `#ifdef DBG` 诊断输出；其余三个文件都由它生成 |
| `minify.py` | 生成脚本：`python3 minify.py sol.cpp submit.cpp --names`（保留变量名）、不带参数（最小）、`--clean`（阅读版） |
| `run.py` / `tune.py` / `gen.py` | 本地批量评测、参数对比、随机场景生成 |
| `cases/` | 测试场景参数；`w/` 为中间结果 |

四个 `.cpp` 是同一个程序：在录制的评测输入上逐字节比对过输出，完全一致。

## 编译与本地评测

```
g++ -std=c++11 -O2 submit.cpp -o submit
python3 run.py bin/submit cases/p1.in -v        # 调用官方 tpj 评测一组
```

## 算法概要

1. **对账**：7 类问题对应的状态全部增量维护——租户账单（固定部分 + 费率 × 时间，沿租户树汇总）、
   配额余量（带撤销栈）、机架间最短路（链路事件只重算受影响的源机架）、机器/机架的 LRU 镜像层缓存、
   告警得分（哈夫曼解码 + AC 自动机）、作业在工作流 DAG 中的松弛量。
2. **时长估计**：作业真实时长不公开且与租户有关，用已完成作业和"已经超期仍在跑"的作业
   按租户学习 真实/估计 比例，并向全局比例收缩。
3. **工作流取舍**：估计剩余关键路径（含准备、排队时间）和剩余成本，按 5 个完工时间情景求期望收益；
   期望收益高于剩余成本才开工，开工后一旦不再划算就 `KILL` 止损。
   调度顺序按"单位核时期望利润"，已开工的、时间紧的优先。
4. **选机**：先按 传输费 + 延迟代价 + 运行费 给机架排序，并向前看一步
   （后继作业将来汇集输入要付的代价）；在最好的几个机架里逐台机器计价（镜像拉取、等待时间）。
   每台机器维护一条预计释放时间线，允许作业"预约"一台正忙但更合适的机器。
5. **超时保险**：按 `clock()` 监控 CPU 时间，落后于预算时逐级降级（先停周期性重估，再隔 tick 调度）。

## 本地测试结果

基准是 GitHub 上一份 OJ 实得 81 分的公开程序（只当作利润标尺，没有参考其策略和代码）。

| | 场景数 | 利润比中位数 | 10% 分位 | 最低 | 不低于基准的比例 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 调参用场景 | 85 | 1.16 | 0.99 | 0.85 | 87% |
| 未参与调参的场景 | 40 | 1.12 | 0.92 | 0.78 | 78% |

- 133 组场景（含 6 组最大规模、2 组官方小样例）：对账全对、非法指令 0。
- CPU 时间（本机 Apple Silicon）：中位 0.08 s，最大规模 0.33 s；基准程序同条件下最大 0.77 s。
- 官方 2 组小样例（T=10 / T=40，远小于正式数据范围）利润低于基准：先验参数是按正式规模设的。

## 复现本地评测

仓库不含任何他人的程序。

1. `kit/` 是课程提供的官方评测包（`1846_samples.zip` 的内容，含 `tpj_win.exe`），原样放在仓库里，版权归课程方。macOS 用 CrossOver 运行，`run.py` 里的 `WINE` 路径按需修改。
2. `inc/bits/stdc++.h` 只是给 macOS clang 用的头文件垫片；Linux 上用 `g++` 时可忽略 `-Iinc`。
3. `python3 gen.py 40 cases/c 9000` 可重新生成场景；`python3 tune.py bin/sol "cases/[abpc]*.in" "KILLK=1"` 做参数对比（需要先用 `-DDBG` 编译出 `bin/sol`，并自备基准结果 `w/ref.json`）。
